## 功能

### 账号与签到

- 森空岛账号只能扫码绑定。一个 QQ 可以绑好几个森空岛账号，默认角色随时能换，也能临时看另一个角色。
- 明日方舟和终末地每天自动签到，绑定的所有账号和角色都签。第一次绑定或新加账号时，马上签一次到、更新一次卫戍榜成绩，
  两款游戏的抽卡记录都拉完后，在绑定的地方发一条消息说结果。
- 绑定保护：二维码发在群里，也只认发指令的那个人。一个森空岛账号只能绑在一个 QQ 上，重新扫码续期也得用原来那个账号。
- 每周体检一次：登录已经失效的绑定，还有既不在机器人任何群里、也不是机器人好友的人的绑定，会被清掉，删之前先备份。

### 终末地

- 角色卡（开盒）：账号概况、据点、全部干员的练度。
- 抽卡记录：绑定后和每天自动同步，存下来就不受官方保留期限影响。赠送和免费十连单独标出来，不算抽数。
  限定寻访、辉光庆典和重构寻访都算限定池。
- 小黑盒导入：补回官方接口已经查不到的早期抽卡记录。只收和绑定 UID 一样的账号，官方记录不会被改。
- 欧非榜：所有绑定用户一起排，不分群。干员统计：所有绑定角色的 6★ 干员持有率、平均潜能和高难出场率。
- 资料库：干员、武器、装备套装和散件的资料卡。认昵称、简称和同音字，也能模糊匹配；带技能数值表、后勤技能，
  还有绑定成员的配装和组队统计（只显示汇总）。数据来自 AKEData，有新的解包数据就自动重建。
  新增干员或武器时在群里通知；重建失败或资料卡缺内容时，私聊告诉超级用户。
- 高难关卡（战争回响、影拓丰碑）：关卡一览，顺序和游戏里一样；关卡机制，算上关卡加成之后的敌人数值和抗性；群内竞速榜。

### 明日方舟

- 角色卡（开盒）：账号概况、助战、基建、全部干员的练度，用明日方舟自己的界面风格。
- 抽卡记录：绑定后和每天自动同步，存下来就不受官方保留期限影响。按卡池开放的年份分页，也可以手动马上更新。
- 小黑盒导入：补回官方接口已经查不到的早期抽卡记录。只收和绑定 UID 一样的账号，官方记录不会被改。
- 卫戍协议战绩，以及所有绑定用户一起排的奖杯榜。
- 干员一览、集成战略战绩，这两个是上游插件的。

### 通知与群功能

- 活动日历和活动开启通知（两款游戏）：有活动开了就往各群发一张图，不 @全体。0 点到 8 点之间开的，8 点统一发。
- 本周任务：两款游戏的周常放在一张图里，发 `/本周任务` 时现做。
- 理智查询；理智回满时在群里 @ 本人（`/理智提醒`）。
- 入群邀请自动同意。好友申请不自动通过。有人加好友、机器人进群，都不说话，没有欢迎语。
- 机器人被移出群或者群解散后，先看群列表里确实没有这个群了，再删掉这个群的关键词回复和发到这个群的理智提醒。
  掉线时漏掉的，每天按群列表补清一次。

### 使用约定

- 所有指令都以 `/` 开头，而且要完全对上才响应，平时聊天不会误触发。指令末尾多打的空格没关系，
  复制来的文字版「@机器人名 /指令」也照样能用。
- 榜单、统计和理智（查询和提醒）都按每个人的默认角色算，随时可以退出统计。例外有两个：
  干员统计的持有率算所有绑定的账号和角色，卫戍榜取奖杯最多的那个明日方舟角色。
- 结果有好几张图的（比如 `/zmd抽卡记录`、`/卫 全部`），会合成一张聊天记录卡片，卡片上标查询人的群名片，卡片后面 @ 他。
  `/签到详情` 的结果也是聊天记录卡片，后面同样 @ 查询人。在私聊或群临时会话里查的，结果只发给本人。
- 有些回复后面（比如 `/卫` 的战绩图后面）会跟一行「还可以发：…」，列出接下来能发的指令。群里的这种提示和文字菜单
  （比如 `/竞速榜` 的目录），提问的人发了其中一条指令，或者 90 秒没人理，就会撤回。私聊和群临时会话里不撤回。
- 图片上传超时的时候，机器人回的是「图片上传较慢…」，不是「生成失败」。图一般过一会儿还是会到，不用重发。

## 部署

只有 NapCat 这一种接法：用一个个人 QQ 号登录 NapCat，机器人通过 OneBot v11 连它。
个人号当机器人容易被风控，NapCat 也已经停更了，这两点你要心里有数。

- 第一次部署，看 [NapCat 部署](docs/deploy-napcat.md)。
- 想改代码或者了解结构，看 [开发说明](docs/development.md)。

| 项目 | 我测过的环境 | 说明 |

## 配置

配置写在 `.env` 里：从 `.env.example` 复制一份，别提交。每一项的说明见 [NapCat 部署](docs/deploy-napcat.md#配置)。

`SUPERUSERS` 至少要填一个 QQ 号。关键词词库的管理指令只给超级用户用，没有超级用户的话，机器人一启动就报错退出。

定时任务用的是 nonebot-plugin-apscheduler 的默认时区 Asia/Shanghai，和服务器的系统时区无关。

上游 nonebot-plugin-skland 用进程的本地时间来格式化日期（苏醒日、抽卡记录日期、4 点刷新倒计时等）。
服务器不在东八区的话，给机器人进程设 `TZ=Asia/Shanghai`，示例 systemd 单元里已经写了。不设的话，
北京时间 0 点到 8 点之间的日期会早一天。

## 指令

所有指令都以 `/` 开头。「可 @他人」的意思是可以在指令后面 @ 群友，看对方的数据。
指令前缀可以互换：`zmd` = `ef` = `终末地`，`mrfz` = `方舟` = `明日方舟`，`skl` = `skd` = `森空岛`，比如 `/ef开盒` 和 `/zmd开盒` 一样。
要分几步的功能，回复里会写接下来发什么（「还可以发：…」），见 [使用约定](#使用约定)。

### 账号

| 指令 | 作用 | 备注 |
|---|---|---|
| `/skl绑定` | 扫二维码绑定森空岛（同 `/skl扫码`）。只能扫码：上游的凭据绑定（`/sk -b`、`/skland bind`）关掉了，发了也不回。手打上游的原始写法 `/sk`、`/skland`，还有依赖插件的 `/user`、`/bind`、`/argot`，都不回，所有功能都用这里列的中文指令 | 群聊、私聊都行 |
| `/skl添加账号` | 再绑一个森空岛账号 | 扫码后核对角色列表，回「确认」才保存 |
| `/skl角色更新` | 刷新已绑定的游戏角色 | |
| `/skl角色` | 看已绑定的账号、角色和序号 | 标着「插件默认」的就是指令默认用的角色 |
| `/skl切换终末地角色 序号` | 换默认角色 | 方舟用 `/skl切换方舟角色 序号` |
| `指令 角色序号` | 临时看另一个角色，不改默认角色；序号见 `/skl角色` | 比如 `/zmd抽卡记录 角色2`、`/zmd开盒 角色2`、`/卫 角色2`；写成 `-r 2` 也行 |
| `/skl解绑` | 解绑，角色和抽卡记录一起删掉 | 先选账号序号或「全部」，再回「确认」 |

## 更新与重启

这个仓库不会再有新版本，`git pull` 拉不到新东西了。停在标签 `napcat-final` 上就行。

**从这个仓库以前的版本换到 `napcat-final`**：先停掉机器人，备份 `data/nonebot_plugin_orm/db.sqlite3`，然后：

```bash
git fetch --tags --force
git checkout napcat-final
.venv/bin/pip install -r requirements.txt -c requirements.lock
.venv/bin/python deploy/orm_cli.py upgrade
```

以前在 `.env` 或 `.env.prod` 里配过 `QQ_BOTS`、`OFFICIAL_BRIDGE_` 开头的设置或 `HELP_MIGRATION_NOTE` 的，换过来之前删掉，这一版用不上它们，留着反而会让帮助图和体检按另一种部署来跑。

装完再启动。`requirements.lock` 是最后一次实测时每个包的版本，装的时候一直带着 `-c requirements.lock`，别单独升级里面的包。
以前照旧文档装的、没单独装过浏览器的，按 [NapCat 部署](docs/deploy-napcat.md) 第 3 步补装一次。

**重启**：只改了插件代码、依赖和数据库都没动的时候，可以用 `.venv/bin/python deploy/restart_when_idle.py` 重启。
它会等到没有指令在处理，也没有战绩收集、卫戍榜统计、账号体检或夜间签到在跑，才去重启，不会打断群友。
这个脚本认的服务名是 `nonebot.service`，而且要当前用户能免密 `sudo`。

自己改代码的话注意：仓库里没有测试（`tests/` 我没公开），也没有任何自动检查，改完要自己试。结构说明见 [开发说明](docs/development.md)。

## 数据与隐私

- `data/` 里的数据库存着用户的森空岛凭证，`.env` 和 `napcat/` 里有访问令牌和 QQ 登录状态。这几个目录和
  `compose.yaml`（可能填了 `WEBUI_TOKEN`）都已经写进 `.gitignore`。不要提交或公开，目录权限保持只有自己能读。
- 账号体检每删一个账号或角色，都先把删掉的行追加进这次的备份 `backups/skland-health/<UTC 时间>.jsonl`。
  一行是一次删除，里面有账号、角色和抽卡记录，也有登录凭证，所以目录权限是 700、文件是 600。中途出错也不会丢。
  要写回数据库，先停掉机器人，然后：

  ```bash
  # 只核对、报数，什么都不写
  .venv/bin/python deploy/restore_health_backup.py backups/skland-health/<备份文件>.jsonl data/nonebot_plugin_orm/db.sqlite3
  # 写回；有任何冲突就一行都不写
  .venv/bin/python deploy/restore_health_backup.py backups/skland-health/<备份文件>.jsonl data/nonebot_plugin_orm/db.sqlite3 --apply
  ```

  加 `--apply` 之前，先看看列出来的人该不该回来：后来自己解绑了的人，也会连同凭证一起被写回。
  写回后再启动机器人，启动时会给这些人补上默认角色。以前的 `.json` 备份也能这样用。
- 小黑盒导入只在本人发指令时，去读他的小黑盒「抽卡分析」页面，原始响应在 `data/heybox_import/` 留一份，方便以后查。
  终末地读的是公开数据。明日方舟的只对登录了的小黑盒账号开放，所以机器人要存一个专用小黑盒账号的登录状态
  （`data/heybox_import/login/`，和森空岛凭证一样别公开）。超级用户私聊发 `/小黑盒登录` 扫一次码，之后每天自动续期。
  小黑盒只有汇总数据：导入的记录里，六星（明日方舟还有五星）和它们的抽数是准的，其余的用占位记录把数量补齐。
- 竞速榜和干员统计只用绑定用户的最佳通关记录和持有干员，配装、组队和持有率只显示汇总。
  不想被统计，发 `/攻略统计 退出`、`/zmd欧非榜 退出`。
- 欧非榜不分群，别的群的人能看到上榜的人的游戏内角色名，群名片只在本群显示。不想上榜发 `/zmd欧非榜 退出`。
- 卫戍榜也不分群，不想上榜发 `/卫戍榜 退出`。
- 机器人日志不记聊天内容（`plugins/log_privacy`），但会有 QQ 号和群号，分享日志前自己打码。
- NapCat 会把收到的消息打到容器日志里，`compose.example.yaml` 已经限制了日志大小。
  systemd 日志留多久按需要设，比如 `MaxRetentionSec=30day`。

## 常见问题

**第一次启动报 `Playwright environment is not set up correctly`，起不来。** 出图用的浏览器没装好。
装完 Python 依赖后要单独装：先 `sudo .venv/bin/playwright install-deps chromium`，再 `.venv/bin/playwright install chromium`，
详见 [NapCat 部署](docs/deploy-napcat.md) 第 3 步。浏览器装在执行安装的那个用户的 `~/.cache/ms-playwright` 下，
systemd 服务要用同一个用户跑，或者安装时和服务里设同一个 `PLAYWRIGHT_BROWSERS_PATH`。

**图片发得很慢或者超时。** 从海外服务器往 QQ 传图，可能每秒只有十几到二十几 KB。大图我已经缩放和压缩过，
`API_TIMEOUT` 也调到了 180 秒，NapCat 那边的上传超时最好也调大一些。超时的时候机器人会回「图片上传较慢…」，
图一般过一会儿还是会到。

**升级了某个依赖以后起不来。** 按 `requirements.txt` 加 `-c requirements.lock` 装，别单独升级。
nonebot-plugin-skland 启动时会被校验（见 [开发说明](docs/development.md#上游插件的校验)），这是故意的：
上游代码一变，本地补丁可能悄悄失效，校验就是防这个。

**图里的中文是方块。** 装上 `fonts-wqy-zenhei` 再重启。

**活动、卡池或下期轮换没显示。** 这些来自 AKEData 的游戏解包数据，游戏更新后可能要晚一点才有，以游戏内公告为准。

**群友加机器人好友没反应。** 机器人不会自动通过好友申请，加了好友也不说话。想让群友私聊用，
就在机器人那个 QQ 号的设置里允许任何人加好友，或者手动同意。是机器人好友的人，每周体检会保留他的绑定。

**机器人退群了，Bison 的订阅还在。** Bison 自己不会在机器人退群时删订阅。我自己的机器人会自动删，但那是我服务器上单独的脚本（要 root 权限改 Bison 的数据库），没放进这个仓库。照这个仓库部署的话，退群后去 Bison 的后台删。

**NapCat 登不上，或者 QQ 更新后用不了。** NapCat 已经停更，这个仓库也不更新了，这类问题不会再有人修。

NapCat 部署本身的问题见 [NapCat 部署的常见问题](docs/deploy-napcat.md#常见问题)。
